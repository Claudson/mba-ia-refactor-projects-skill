PHASE 3: REFACTORING COMPLETE

Strategy

Extração completa de monolito — a Fase 1 classificou o projeto como monolítico/sem camadas (models.py concentrava SQL, regra de negócio e serialização dos três domínios), então não havia estrutura aproveitável: cada função foi movida para a camada correta e os três arquivos originais foram apagados.

Findings Resolved

- F01 / Segredo hardcoded → SECRET_KEY sai do código para os.environ; ausente, gera chave efêmera com warning; /health não devolve mais a chave.
- F02 / SQL Injection → todas as queries parametrizadas (? + tupla); busca dinâmica monta lista de cláusulas fixas + lista de parâmetros.
- F03 / Senhas em texto puro → generate_password_hash/check_password_hash na criação, no login e no seed; o SQL só busca por email.
- F04 / Exposição de dados → serializers com CAMPOS_PUBLICOS (sem senha), /health só com status/contagens, str(e) substituído por mensagem genérica + log no servidor.
- F05 / Endpoints admin abertos → guard require_admin (X-Admin-Token, hmac.compare_digest); sem ADMIN_TOKEN configurado os endpoints ficam desabilitados (403); /admin/query só aceita um SELECT, em conexão mode=ro.
- F06 / Debug e CORS → DEBUG, HOST, PORT e CORS_ORIGINS vêm do ambiente, com debug desligado, bind em 127.0.0.1 e CORS desabilitado por padrão.
- F07 / God Module → models.py dividido em 4 models por agregado + 2 services + 6 controllers + 6 blueprints; database.py dividido em conexão/schema/seed.
- F08 / Fat controllers → validações nos validators, regras de pedido/relatório no service, notificações no notification_service; handlers de rota com 2–5 linhas.
- F09 / Sem DI → models recebem a conexão por parâmetro; controllers e services recebem suas dependências do composition root.
- F10 / Estado global → conexão por requisição em flask.g com teardown_appcontext; sem global, sem check_same_thread=False.
- F11 / Escrita não atômica → criação de pedido dentro de with conn: (commit/rollback atômico) e baixa de estoque condicional (WHERE estoque >= ?) contra corrida.
- F12 / N+1 → listagem de pedidos em uma query com LEFT JOIN e agrupamento em memória; relatório em um GROUP BY; produtos do pedido em um IN (...); health em 3 contagens diretas.
- F13 / Duplicação → um serializer por entidade, um validador compartilhado por criar/atualizar, listagem de pedidos parametrizada pelo filtro.
- F14 / Validação fraca → tipo/faixa/forma validados na borda; corpo ausente, preço não numérico, item malformado, quantidade ≤ 0, usuario_id inexistente e email duplicado passam a devolver 400/404 em vez de 500 ou corrupção silenciosa.
- F15 / Erros → hierarquia AppError/ValidationError/NotFoundError/BusinessRuleError/ConflictError/Unauthorized/Forbidden + @app.errorhandler central; 404/405 do Flask agora em JSON.
- F16 / Integridade referencial → FKs declaradas (ON DELETE RESTRICT / CASCADE), PRAGMA foreign_keys = ON em toda conexão, exclusão de produto com pedidos bloqueada, reset em transação única na ordem das FKs.
- F17 / print → módulo logging com nível por ambiente; emails removidos das mensagens de log.
- F18 / Magic numbers → FAIXAS_DESCONTO, STATUS_VALIDOS, CATEGORIAS_VALIDAS, NOME_MIN/MAX_TAMANHO nos models; versão e porta na config.
- F19 / Nomenclatura → id → produto_id/usuario_id/pedido_id; cursor2/cursor3 eliminados junto com o N+1.
- F20 / Imports não usados → arquivos antigos apagados; nenhum import morto nos novos módulos.
- F21 / Condicionais → if not itens:, early return sem else, filtros numéricos comparados com is not None (agora preco_min=0 filtra).

Nenhum finding ficou sem resolução.

Intentional Contract Changes

| Endpoint | Mudança | Motivo |
|---|---|---|
| GET /health | Removidos secret_key, db_path, debug, ambiente; mantidos status, database, counts, versao | F01/F04 — vazava a chave de assinatura e a configuração interna |

| DELETE /produtos/<id> | Produto referenciado por pedidos → 409 (antes 200, deixando histórico órfão) | F16 |
| app.run | Bind padrão 127.0.0.1 e debug desligado (configuráveis) | F06 |
| CORS | Desabilitado por padrão, habilitado por CORS_ORIGINS | F06 |
| Login com loja.db antigo | Senhas em texto puro do banco anterior não autenticam; apagar loja.db recria o seed com hash | F03 (documentado no README) |
